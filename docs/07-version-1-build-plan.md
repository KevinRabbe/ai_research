# Version 1: First Runnable Plural-Cognition Experiment

## 1. Naming

The existing Version 0 document defines the scientific protocol and falsification boundary.

Version 1 is the first runnable implementation of that protocol.

```text
Version 0 = specification, controls, metrics, and scientific gate
Version 1 = generator + models + population protocol + controlled experiment
```

Version 1 is not intended to be generally useful. It exists to produce interpretable evidence about the central mechanism.

## 2. Central question

> Can several small models with the same architecture but independently learned weights, all receiving the same complete evidence, produce distinct partial hypotheses that a structured synthesis process combines into a verified solution better than every individual model and simpler aggregation methods?

The experiment must be capable of rejecting this implementation.

## 3. Questions Version 1 must answer

### Q0 — Is the benchmark scientifically usable?

Can exact ground truth distinguish:

- a fully correct mechanism;
- a partially correct mechanism;
- an evidence-consistent but incomplete mechanism;
- an invalid synthesis;
- a semantically equivalent solution written differently?

### Q1 — Does independently learned weight diversity create useful functional diversity?

Compare:

```text
different checkpoints
versus
multiple trajectories from one checkpoint
```

Useful diversity means different valid clauses, boundary conditions, counterexamples, predictions, or failure modes—not merely different token sequences.

### Q2 — Does structured synthesis add capability?

Does the synthesized result exceed:

- the strongest individual member;
- best-of-N selection;
- majority voting;
- confidence-weighted selection;
- same-weight population synthesis;
- a no-synthesis ablation?

### Q3 — Is any gain genuinely multi-source and novel?

For a claimed synthesis event:

- the final complete mechanism must be absent from every initial member output;
- necessary components must originate from at least two members;
- removing one necessary contribution must break or reduce the final solution;
- exact evaluation must confirm the synthesized mechanism.

### Q4 — Does the result survive held-out structures and repeated populations?

A positive result must survive:

- unseen generator seeds;
- held-out rule compositions;
- multiple independently trained populations;
- matched inference and verification budgets.

### Q5 — Can evidence defeat popularity?

When a majority follows the same shortcut but a minority member supplies a decisive valid clause or counterexample, can synthesis preserve and use that minority contribution?

## 4. Questions deliberately excluded

Version 1 does not test:

- recursive self-improvement;
- dynamic compute allocation;
- learned communication;
- heterogeneous model architectures;
- external web research;
- natural-language generality;
- product usefulness;
- autonomous code modification;
- long-horizon evolutionary archives.

Those mechanisms would make a negative result impossible to diagnose.

## 5. Version 1 overview

```text
procedural world generator
        ↓
complete evidence packet
        ↓
4 independently trained small models
        ↓
4 private hypothesis packets
        ↓
canonical claim and program extraction
        ↓
provenance-preserving structured workspace
        ↓
bounded synthesis from member-proposed components
        ↓
consistency checks against visible evidence
        ↓
one final mechanism or explicit unresolved state
        ↓
hidden exact evaluator
```

The evaluator must never expose hidden ground truth to the members or synthesizer.

## 6. Primary task family: Boolean Mechanism Worlds

### 6.1 Why this family

The first task family should be abstract enough to avoid pretrained world knowledge, structured enough to expose partial knowledge, and exact enough to eliminate subjective judging.

Each world contains:

- a small set of Boolean properties;
- a hidden conditional mechanism;
- observations and interventions generated by that mechanism;
- distractor correlations or near-miss explanations;
- one or more held-out prediction queries.

### 6.2 Hidden mechanism grammar

The initial grammar should remain bounded and exhaustively evaluable.

Example conceptual forms:

```text
A AND B
A OR B
A AND NOT B
(A AND B) OR C
A UNLESS B
IF C THEN (A AND B) ELSE D
```

The implementation should use a canonical abstract syntax tree rather than natural-language rules.

Provisional limits:

```text
input variables:       6–10
expression depth:      2–4
atomic clauses:        2–5
context branches:      at most 1 initially
exceptions:            at most 1 initially
```

The limits are preflight values, not permanent architectural commitments.

### 6.3 Evidence generation

For each hidden mechanism:

1. generate candidate observations and interventions;
2. select an identifying or near-identifying evidence set;
3. include positive, negative, boundary, and counterexample cases;
4. prevent trivial frequency shortcuts;
5. reserve unseen assignments for final evaluation.

The evidence given to every member must be identical and complete.

### 6.4 Exact semantics

For at most ten Boolean variables, candidate mechanisms can be evaluated exhaustively over all assignments.

This permits:

- semantic equivalence rather than string equality;
- exact completeness scores;
- exact counterexample generation;
- exact hidden evaluation;
- proof that two differently written mechanisms represent the same function.

### 6.5 Dataset splits

```text
train:
  known grammar families, online procedural seeds

development:
  unseen seeds from known structures

hidden-seed test:
  unseen seeds and feature permutations

held-out-composition test:
  combinations of known operators not used together during training

adversarial test:
  misleading correlations, near-miss rules, shortcut traps
```

The held-out evaluator configuration must be fixed before the final run.

## 7. Optional replication family

A positive result from one Boolean task family is not evidence of a general mechanism.

After the core signal, replicate on one structurally different exact domain, preferably:

### Finite-State Mechanism Worlds

Members infer a small hidden state machine from input/output traces and interventions.

This changes the representation from static Boolean composition to sequential transition structure while preserving exact verification.

Version 1 may be considered a successful first experiment before this replication, but broader claims require it.

## 8. Model architecture

### 8.1 Model type

Use a small decoder-only transformer with a custom symbolic vocabulary.

Reasons:

- identical tensor shapes across members;
- straightforward autoregressive structured output;
- no dependence on an external tokenizer or pretrained language knowledge;
- inexpensive independent training;
- direct comparison between different-weight and same-weight populations.

### 8.2 Parameter preflight

Do not select the final parameter count by intuition alone.

Run three scales:

```text
Tiny:    approximately 4–6 million parameters
Small:   approximately 8–12 million parameters
Medium:  approximately 14–20 million parameters
```

Choose the smallest scale whose individual exact semantic accuracy is nontrivial but not saturated.

Target calibration range:

```text
individual exact accuracy: approximately 20%–70%
```

Interpretation:

- below the range: individual minds may be too weak to contribute meaningful structure;
- above the range: the task may be too easy to reveal synthesis gain.

### 8.3 Provisional tensor configuration

A likely starting region is:

```text
layers:          6–8
d_model:         256–384
attention heads: 8
FFN ratio:       4x
context:         384–512 tokens
vocabulary:      compact symbolic vocabulary
precision:       BF16 or FP16 where stable
```

The exact configuration must be generated from one source of truth and recorded in every checkpoint manifest.

### 8.4 Population size

Start with:

```text
N = 4 members
```

Then run an ablation at:

```text
N = 2 and N = 8
```

The first question is whether synthesis exists, not whether more members always help.

## 9. Training conditions

### 9.1 Core different-weight population

All members share:

- architecture;
- tokenizer;
- objective;
- total training examples;
- total optimizer steps;
- optimizer family;
- evaluation access.

They differ in:

- parameter initialization;
- data order;
- dropout and training randomness;
- independent optimizer state.

### 9.2 Learning-history diversity condition

If seed-only diversity is weak, test a controlled curriculum-diversity condition.

All members still see the same total training distribution, but in different phase orderings, such as:

```text
member A: conjunctions → exceptions → branches
member B: branches → conjunctions → exceptions
member C: exceptions → branches → conjunctions
member D: mixed curriculum throughout
```

This tests whether useful diversity requires different developmental histories rather than random initialization alone.

### 9.3 Same-weight control

Clone one trained checkpoint N times.

Generate independent trajectories using matched decoding randomness and the same total generated-token budget as the different-weight population.

This isolates learned functional diversity from repeated sampling.

### 9.4 Repeated populations

Qualification should use multiple independently trained populations rather than one lucky set of checkpoints.

Provisional qualification target:

```text
3–5 independent populations
4 members per population
```

The exact number should follow the compute preflight and preregistered power analysis.

## 10. Hypothesis packet

Each member receives the same evidence but cannot see the other members during the divergence round.

The output must follow a constrained grammar similar to:

```text
PROVISIONAL_PROGRAM <canonical program>
CLAIM <atomic or composite clause>
SUPPORT <evidence identifiers>
COUNTEREXAMPLE <evidence identifiers or NONE>
UNCERTAIN <variables or relations>
PREDICTION <assignment> -> <outcome>
CONFIDENCE <bucket>
END
```

The raw output remains immutable and receives a content hash.

A malformed packet is an explicit failure, not silently repaired by a judge model.

## 11. Structured workspace

The workspace stores canonical records:

```text
claim_id
canonical_expression
source_member
source_path
supporting_evidence
contradicting_evidence
assumptions
predictions
confidence
semantic_equivalence_class
verification_status
dependencies
```

The workspace must preserve:

- raw member packets;
- canonicalized claims;
- all provenance edges;
- rejected combinations;
- verifier results;
- final synthesis derivation.

## 12. Version 1 synthesis engine

The first synthesis engine should be deterministic and bounded.

It may:

- canonicalize semantically equivalent subexpressions;
- retain unique valid clauses;
- detect direct contradictions;
- combine member-proposed clauses with bounded AND, OR, NOT, exception, or branch operations;
- replace an overbroad rule with a member-proposed boundary condition;
- generate a small candidate set;
- check candidates against visible evidence;
- prefer simpler candidates when evidence fit is equal.

It must not:

- enumerate the entire hidden grammar;
- access hidden assignments or ground-truth programs;
- introduce arbitrary atoms never proposed by a member;
- use an unrestricted language model as an unmeasured judge;
- silently remove provenance.

### 12.1 Why deterministic synthesis first

A learned synthesizer would combine two unknowns:

```text
Does plural cognition work?
Does this new learned controller work?
```

The deterministic scaffold isolates the first question. Learned synthesis comes only after a positive signal.

### 12.2 Novel synthesis definition

A final candidate counts as novel synthesis only when:

1. it is semantically correct on hidden evaluation;
2. no complete member proposal is semantically equivalent to it;
3. at least two necessary components have different member provenance;
4. removing a necessary component or its sole source prevents the same result under the fixed synthesis budget.

## 13. Verification boundary

### Visible consistency checker

Available during inference:

- execute a candidate on the provided evidence;
- locate visible contradictions;
- compare semantic equivalence on visible assignments;
- calculate candidate complexity.

### Hidden evaluator

Unavailable during inference:

- ground-truth mechanism;
- exhaustive unseen truth table;
- held-out interventions;
- final semantic-equivalence score.

The visible checker helps eliminate impossible candidates. It cannot reveal the answer.

## 14. Experimental systems

### B — different-weight structured synthesis

The proposed system.

### C — same-weight structured synthesis

Same orchestration, but cloned weights with independent trajectories.

### D1 — different-weight majority vote

Vote over complete member programs after canonical semantic grouping.

### D2 — different-weight best-of-N

Select the complete member program with the best visible evidence consistency and fixed tie-breaking.

### D3 — ordinary debate

Members exchange natural-language or symbolic critiques under the same generated-token budget, followed by a fixed final selector.

### E — no-synthesis ablation

Use the workspace and checks, but final output must be one unmodified complete member proposal.

### F — extra-sampling control

One checkpoint receives the same total trajectory count and generated-token budget as the entire population.

### A — larger monolithic control

After the core mechanism shows a signal, train one larger model and compare under matched inference FLOPs and separately under matched total active parameters.

Do not delay the cheap B/C/D/E/F comparison while waiting for A.

## 15. Compute matching

Every reported comparison must record separately:

- model forward FLOPs or a reproducible proxy;
- generated tokens;
- number of independent trajectories;
- visible verifier calls;
- CPU synthesis operations;
- wall-clock time;
- peak GPU memory;
- total checkpoint storage.

For the primary B/C/D/E/F comparison:

- use the same number of model trajectories;
- use the same token budget;
- use the same visible evidence;
- give every applicable system the same candidate-consistency budget;
- report deterministic synthesis cost rather than pretending it is free.

## 16. Metrics

### Primary endpoint

```text
collective exact semantic accuracy
minus
best preregistered simpler baseline accuracy
```

The strongest simpler baseline may be the strongest individual, best-of-N, extra sampling, or another preregistered control.

### Secondary endpoints

- strongest individual accuracy;
- synthesis gain over strongest individual;
- gain over same-weight synthesis;
- gain over best-of-N;
- novel synthesis rate;
- multi-source necessity rate;
- minority rescue rate;
- pairwise error correlation;
- unique valid claim count;
- contribution entropy;
- calibration of confidence buckets;
- coordination cost;
- malformed-output rate;
- invalid-synthesis rate.

### Trace-level evidence

Every claimed novel synthesis should include a machine-readable trace:

```text
member packet hashes
→ extracted clauses
→ provenance graph
→ generated candidate
→ visible consistency result
→ hidden evaluator result
→ source-removal ablation
```

## 17. Provisional qualification criteria

Final thresholds must be preregistered after the benchmark and scale preflights, but the initial target should be demanding.

A strong Version 1 result should require:

1. System B has positive primary-endpoint gain on hidden evaluation.
2. The paired 95% bootstrap confidence interval for the gain excludes zero.
3. The gain is practically meaningful, provisionally at least 5 percentage points.
4. B beats same-weight synthesis, best-of-N, and no-synthesis controls.
5. The direction reproduces in at least 4 of 5 independent populations, or an equivalently strict preregistered criterion.
6. Correct novel synthesis events are traceable and nontrivial.
7. At least some successes require multiple members under source-removal ablation.
8. The result survives held-out rule compositions.
9. The result remains after matched trajectory, token, and verifier budgets.

A weak positive result should be reported separately rather than promoted as proof.

## 18. Failure interpretations

### Different weights do not exceed same-weight sampling

Possible conclusions:

- seed-only training did not create useful diversity;
- the task has one dominant representation;
- the models converged too strongly;
- the model is too small or too accurate;
- weight diversity is not the right initial mechanism.

Next test: controlled curriculum diversity before abandoning plural cognition.

### Different-weight members are diverse, but synthesis adds no gain

The integration mechanism is the failure point.

Next tests:

- better claim normalization;
- better provenance use;
- improved bounded composition operators;
- explicit expertise calibration;
- hierarchical synthesis.

### Best-of-N matches structured synthesis

The population helps by increasing search coverage, but no collective construction has been demonstrated.

Do not proceed to self-improvement on that basis.

### Synthesis gains disappear on held-out compositions

The synthesizer or members learned template-specific recombination.

Redesign the task distribution or integration mechanism.

### The strongest individual consistently beats the collective

Coordination is destroying information or compromising with weaker claims.

This is a direct negative result for the current architecture.

### All models fail or all models succeed

The benchmark is miscalibrated. Adjust task depth, model scale, evidence density, or training curriculum before interpreting population behavior.

## 19. Build sequence

### V1.0 — generator and exact evaluator

Deliver:

- canonical mechanism AST;
- random mechanism generator;
- evidence generator;
- visible consistency checker;
- hidden exhaustive evaluator;
- semantic-equivalence tests;
- split manifest;
- deterministic unit tests.

Gate:

The generator must never produce ambiguous or incorrectly labeled qualification tasks under the declared grammar.

### V1.1 — one-member learning preflight

Deliver:

- custom tokenizer;
- transformer implementation;
- training loop;
- checkpoint manifest;
- three-size capability curve;
- exact semantic evaluation;
- memory and throughput measurements.

Gate:

Choose the smallest nontrivial, unsaturated model scale.

### V1.2 — independent population

Deliver:

- at least four independent checkpoints;
- same-weight cloned control;
- deterministic divergence runner;
- hypothesis packet parser;
- functional-diversity report.

Gate:

Members must exhibit measurable differences in errors or valid components. Token-level variation alone is insufficient.

### V1.3 — structured synthesis

Deliver:

- canonical claim workspace;
- contradiction detection;
- bounded composition engine;
- provenance graph;
- visible consistency scoring;
- source-removal ablation.

Gate:

Synthetic unit fixtures must prove the engine can combine supplied valid fragments without accessing hidden truth.

### V1.4 — controlled comparison

Run B, C, D1, D2, E, and F under matched budgets.

Publish:

- every config;
- every checkpoint identity;
- every task split identity;
- raw predictions;
- synthesis traces;
- all negative and null results.

### V1.5 — replication and large-model control

Only after a core signal:

- repeat across independent populations;
- run held-out compositions;
- add System A;
- replicate on Finite-State Mechanism Worlds.

A claim without the corresponding manifests and raw trace references is not qualified evidence.

## 22. Immediate first implementation slice

The first code change should contain only:

1. the Boolean mechanism AST;
2. semantic execution;
3. canonicalization;
4. exhaustive equivalence checking;
5. deterministic random generation;
6. unit tests for equivalence, exceptions, branches, and invalid programs.

Do not begin model training until the world generator and evaluator are trustworthy.

## 23. Version 1 stopping rule

Version 1 earns expansion only when structured different-weight synthesis shows reproducible, traceable, compute-controlled gain.

Otherwise:

```text
identify which assumption failed
→ redesign only that layer
→ rerun the cheapest decisive control
→ preserve the negative result
```

The purpose of Version 1 is not to protect the architecture. It is to determine whether this implementation of different cognitive paths can create knowledge that simpler systems cannot.
