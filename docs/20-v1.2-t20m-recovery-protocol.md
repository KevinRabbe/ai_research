# V1.2-t20m recovery protocol

## Status

This document freezes the next capability-recovery intervention after the negative V1.2 GPU screen.

V1.2 trained the PC-29M, PC-44M, and PC-64M capacity ladder for a nominal 10,000,000 training tokens at initialization seeds 101 and 102. All six runs completed their frozen 306 optimizer steps and 10,027,008 effective padded tokens.

The greedy exact-accuracy results were:

| Model | Seed 101 | Seed 102 | Mean |
| --- | ---: | ---: | ---: |
| PC-29M | 0.080078 | 0.062500 | 0.071289 |
| PC-44M | 0.121094 | 0.085938 | 0.103516 |
| PC-64M | 0.121094 | 0.115234 | 0.118164 |

All three means are below the predeclared 0.20 minimum exact-accuracy boundary. No V1.2 scale qualifies and seeds 103/104 must not be trained from this screen.

## Diagnostic basis

The PC-64M checkpoint learning curve was evaluated at the already-frozen token checkpoints. Exact accuracy continued to rise strongly between 5M and 10M tokens:

| Token checkpoint | Seed 101 | Seed 102 | Mean |
| --- | ---: | ---: | ---: |
| 1M | 0.000000 | 0.000000 | 0.000000 |
| 2M | 0.000000 | 0.000000 | 0.000000 |
| 5M | 0.044922 | 0.046875 | 0.045898 |
| 10M | 0.121094 | 0.115234 | 0.118164 |

Parsing also converged to 1.0 for both PC-64M seeds by 10M tokens. This supports undertraining as the next controlled hypothesis more strongly than another immediate increase in model capacity.

The V1.2 evaluations also exposed an implementation defect in the semantic diagnostic: exhaustive semantic distance was an integer count of disagreeing truth-table assignments but was subtracted directly from 1.0. That defect affects semantic-accuracy reporting only; greedy exact equivalence and parse rate are computed independently. The recovery head corrects semantic accuracy by dividing the disagreement count by the exhaustive assignment count and adds a regression test for a valid program with exactly 0.5 semantic accuracy.

## Frozen intervention

V1.2-t20m changes exactly one capability axis relative to V1.2:

```text
nominal training-token budget: 10,000,000 -> 20,000,000
```

The following remain frozen:

- model family and order: PC-29M, PC-44M, PC-64M;
- initialization seeds: 101 and 102;
- data seed: 20260806;
- sequence length: 256;
- target tokens per optimizer step: 32,768;
- optimizer configuration;
- validation count and ordered validation shard: 512 examples;
- greedy generation for scale selection;
- minimum parse rate per seed: 0.95;
- mean exact-accuracy capability band: 0.20 through 0.70;
- selection rule: smallest qualifying model.

The recovery run identity is `v1.2-t20m-screen`.

## Checkpoint schedule

Each run uses the frozen checkpoint schedule:

```text
1M, 2M, 5M, 10M, 15M, 20M nominal tokens
```

At a 32,768-token optimizer batch, a 20,000,000 nominal-token budget resolves to 611 optimizer steps and 20,021,248 effective padded training tokens.

With sequence length 256, each optimizer step consumes 128 examples, so each execution requires exactly 78,208 training examples.

## Training-data extension

The existing deterministic training shard is preserved:

```text
train-000
start_index = 0
example_count = 39,168
```

Only the missing contiguous suffix is generated:

```text
train-001
start_index = 39,168
example_count = 39,040
```

Together the ordered shards contain exactly 78,208 examples. `train-001` must use the same data seed and training-data configuration as `train-000`. The validation dataset is not rebuilt or extended.

## Execution and provenance

Because the semantic fix and recovery planner change repository code, all GPU-bound V1.2-t20m artifacts must be regenerated against the new exact Git head:

1. run the CUDA preflight for PC-29M, PC-44M, and PC-64M;
2. generate `train-001` and preserve `train-000` unchanged;
3. resolve the six-run V1.2-t20m plan from that exact preflight;
4. bind both ordered training manifests plus the existing validation manifest into new execution manifests;
5. dry-run all six executions;
6. train all six executions from their frozen initialization seeds under the 20M intent;
7. greedily evaluate all six final checkpoints;
8. run scale selection with protocol label `v1.2-t20m` and the unchanged gates.

The 10M V1.2 checkpoints and evaluations remain preserved as a negative result and diagnostic record. They are not relabeled as V1.2-t20m artifacts.

## Decision rule

If at least one scale satisfies both the parse gate and the 0.20-0.70 mean exact-accuracy band, select the smallest qualifying model and only then add seeds 103 and 104 to form the four-member population.

If no scale qualifies, preserve V1.2-t20m as another negative result. Do not lower the gate, choose the best scale post hoc, or train population seeds 103/104. Diagnose the next single intervention from the frozen learning curves and evaluation artifacts.
