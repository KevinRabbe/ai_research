## Fixed vocabulary

The implemented vocabulary contains exactly **75 tokens**:

```text
22 structural, operator, Boolean, and control tokens
20 variable tokens: V0 through V19
33 bounded number tokens: N0 through N32
```

There is no unknown token.

Any unsupported token, variable, number, or token ID fails closed. This prevents malformed data from being silently mapped into a generic representation.

## Public-task representation

The model receives only semantically relevant public information:

```text
variable order
visible assignments
visible outputs
intervention variable
intervention source and destination case indices
whether the intervention changed the output
```

Opaque identifiers are deliberately removed:

```text
task fingerprint
original evidence case IDs
original intervention IDs
```

Those identifiers do not help solve the mechanism. Retaining them would waste context and could permit accidental shortcut learning.

Decoding creates stable local identifiers such as `C0`, `C1`, and `I0`. Round trips therefore preserve all model-visible semantics rather than arbitrary external names.

## Intervention validation

The codec independently checks that every intervention:

1. references visible cases;
2. changes exactly one assignment bit;
3. identifies that changed variable correctly;
4. reports `changed_output` consistently with the referenced outputs.

A malformed intervention is rejected before training or inference.

## Mechanism representation

Mechanisms use a bounded prefix grammar:

```text
TRUE
FALSE
V0 ... V19
NOT <expr>
AND <arity> <expr> ...
OR <arity> <expr> ...
ITE <condition> <when_true> <when_false>
```

Properties:

- parsing is deterministic;
- no natural-language parser or judge model is required;
- complete consumption is mandatory;
- trailing or truncated tokens fail;
- AND/OR arity is bounded;
- expression depth and node count are bounded;
- variables outside the current task are rejected before normalization;
- valid mechanisms are normalized after parsing.

## Decoder-only training sequence

The codec constructs one causal sequence:

```text
<BOS>
<TASK> ... public evidence ...
<ANSWER> ... canonical mechanism ...
<EOS>
```

It also produces a label mask. Prompt tokens and the `<ANSWER>` boundary are not scored; mechanism tokens and the final `<EOS>` are scored.

The mask is explicit because the training loop must not accidentally reward reconstruction of public evidence instead of learning the hidden mechanism.

## Context-length result

For `V` variables, `E` visible evidence cases, and `I` interventions, the public-task length is:

\[
T_{task} = 9 + V + E(V + 3) + 8I
\]

At the initial maximum visible evidence budget:

```text
6 variables, 16 evidence cases, 3 interventions
→ 183 public-task tokens
→ sufficient room for a bounded answer inside 256 tokens

10 variables, 16 evidence cases, 3 interventions
→ 251 public-task tokens
→ insufficient room for most answers inside 256 tokens
```

Therefore V1.1 freezes the first learning preflight at:

```text
variable count: 6
maximum full causal sequence: 256 tokens
```

Ten-variable worlds are not discarded. They move to a later context-length ablation using 384 or 512 tokens after the six-variable learning contract works.

## Exact decoder family

All three models share one implementation:

```text
decoder-only causal transformer
pre-normalization RMSNorm
bias-free projections
4x GELU feed-forward block
rotary positions
causal scaled-dot-product attention
tied input/output token embeddings
head dimension 64
context 256
vocabulary 75
```

The model precomputes rotary and causal-mask buffers once. The hot forward path does not scan token values or perform `.item()` validation that would synchronize a CUDA stream. Token validity is owned by the codec and collator trust boundaries.

Using:

\[
P = L(12d^2 + 2d) + Vd + d
\]

with `V = 75`:

```text
PC-4M
layers: 6
width: 256
heads: 4
parameters: 4,741,120

PC-10M
layers: 8
width: 320
heads: 5
parameters: 9,859,840

PC-18M
layers: 10
width: 384
heads: 6
parameters: 17,731,584
```

Every model constructor checks its actual parameter count against the formula and fails if they differ.

## CPU qualification

The local test suite establishes:

- exact parameter counts for all three configurations;
- deterministic evaluation-mode output;
- tied embedding/output projection behavior through a single weight matrix;
- padding invariance for valid prefix logits;
- answer-only causal cross entropy;
- finite forward and backward passes;
- finite embedding gradients;
- successful forward/backward execution for PC-4M, PC-10M, and PC-18M;
- rejection of invalid tensor shapes and dtypes.

These are CPU structural tests. They do not establish training speed or learning capability.
