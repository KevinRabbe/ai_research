# V1.1 Model Scale Selection

## Decision

Use an approximately **9.86 million parameter decoder transformer** as the primary Version 1.1 candidate.

Bracket it with:

- an approximately **4.74M** lower candidate;
- an approximately **17.73M** upper candidate.

The final experimental model is not selected by maximum size or by whether it fits in VRAM. It is selected as the **smallest model that reaches nontrivial but unsaturated hidden exact accuracy while producing useful disagreement across independently trained seeds**.

```text
lower bracket:   4.74M
primary:         9.86M
upper bracket:  17.73M
```

## Why approximately 10M is the primary candidate

The first Boolean Mechanism World is a narrow symbolic domain with a small vocabulary and short contexts. It does not require broad linguistic knowledge or a large embedding table.

The main capacity requirements are:

- composing several Boolean clauses;
- retaining evidence across a short sequence;
- generating a canonical structured mechanism;
- representing boundary conditions and exceptions;
- producing different learned error patterns across seeds.

A 10M model is large enough to contain multiple transformer layers and a 320-dimensional residual stream, but small enough to train many independent checkpoints and controls on one RTX 4060 Ti 16GB.

The objective is repeated controlled science, not one maximal run.

## Fixed architecture family

All three candidates now use one implemented architecture:

```text
decoder-only causal transformer
pre-normalization RMSNorm
bias-free linear layers
fixed 4x GELU feed-forward block
causal scaled-dot-product attention
rotary positions
head dimension: 64
tied token embedding and output weights
fixed symbolic vocabulary: 75 tokens
maximum full causal context: 256 tokens initially
initial Boolean variables: 6
```

The feed-forward implementation is identical across scales. SwiGLU can be tested later as an architectural ablation rather than mixed into the first scale comparison.

## Exact configurations

The implementation uses:

- vocabulary size: 75, fixed by the qualified symbolic codec;
- tied token/output embedding;
- rotary positions, so no learned positional table;
- two RMSNorm weight vectors per block plus one final RMSNorm;
- bias-free attention and feed-forward projections;
- feed-forward width: `4 * d_model`.

The exact count is:

\[
P = L(12d^2 + 2d) + Vd + d
\]

where `L` is layer count, `d` is model width, and `V = 75`.

## Context-length boundary

The qualified codec measures the whole decoder sequence, not only the public task.

At the initial evidence maximum:

```text
6 variables + 16 evidence cases + 3 interventions
→ 183 public-task tokens
→ room for a bounded canonical answer inside 256 tokens

10 variables + 16 evidence cases + 3 interventions
→ 251 public-task tokens
→ insufficient room for most answers inside 256 tokens
```

Therefore the first learning preflight freezes:

```text
variables: 6
full prompt-plus-answer context: 256 tokens
```

Ten-variable tasks move to a later 384/512-token context ablation. They must not silently enter the first training distribution.

See `docs/09-v1.1-symbolic-codec.md` for the exact grammar and CPU model contract.

## Hardware fit

Target GPU:

```text
NVIDIA GeForce RTX 4060 Ti
VRAM: 16 GB GDDR6
CUDA cores: 4352
CUDA capability: 8.9
```

Parameter storage is not the limiting factor. Under an intentionally conservative mixed-precision AdamW estimate of approximately 18 bytes per parameter before activations and temporary buffers:

```text
PC-4M:   about 0.09 GB
PC-10M:  about 0.18 GB
PC-18M:  about 0.32 GB
```

Activations, attention buffers, batch size, and framework overhead will consume much more than the persistent parameter state. All three candidates remain far below the 16GB parameter-capacity boundary at a 256-token context.

Use PyTorch automatic mixed precision and scaled-dot-product attention. CUDA kernel selection and actual memory use remain measurements, not assumptions.

## What the 32GB system-RAM upgrade changes

Moving from 16GB to 32GB system RAM is useful for:

- keeping generated datasets and evaluation artifacts in memory;
- running data-generation workers without paging;
- retaining several checkpoints and result tables during analysis;
- avoiding host-memory pressure while the GPU trains.

It does not increase GPU VRAM. The replacement motherboard supports the intended DDR5 kit, so no memory-generation compatibility blocker remains.

## Preflight protocol

### Stage 0 — codec and CPU model contract

Implemented locally:

1. fixed vocabulary of exactly 75 tokens;
2. fixed 256-token full causal-sequence contract;
3. exact model-visible public-task round trips;
4. canonical mechanism round trips;
5. malformed-output and intervention rejection;
6. explicit answer-only causal label mask;
7. all three model configurations;
8. exact parameter-count assertions;
9. deterministic CPU evaluation output;
10. CPU forward/backward passes for PC-4M, PC-10M, and PC-18M;
11. padding-invariance and finite-gradient tests.

GitHub Actions qualification and target-machine CUDA execution are recorded separately because CPU success does not establish CUDA throughput or learning capability.

### Stage 1 — throughput and memory sweep

For each model, test sequence lengths `128` and `256` and microbatches:

```text
16, 32, 64, 128, 256
```

Stop increasing the microbatch when:

- CUDA out-of-memory occurs;
- peak allocated memory exceeds 13.5GB;
- throughput stops improving materially.

Reserve approximately 2GB for allocator fragmentation, evaluation, and temporary buffers.

Record:

- examples per second;
- tokens per second;
- milliseconds per optimizer step;
- peak allocated VRAM;
- peak reserved VRAM;
- host RAM;
- GPU utilization;
- precision mode;
- selected attention backend.

Use gradient accumulation only to equalize the global token batch after the best microbatch is known.

### Stage 2 — short learning curves

Train two seeds of each scale on an identical initial token budget:

```text
10 million training tokens
```

Reject configurations that:

- fail to reduce validation loss;
- produce mostly malformed programs;
- remain near chance on all semantic metrics;
- show numerical instability;
- are much slower without measurable learning benefit.

### Stage 3 — capability calibration

Continue surviving candidates to:

```text
50 million training tokens
```

Use at least three independent seeds per candidate.

Measure:

- hidden exact semantic accuracy;
- visible-evidence consistency;
- malformed-output rate;
- semantic distance from the hidden target;
- clause and operator recovery;
- held-out-composition accuracy;
- pairwise error correlation between seeds;
- unique valid components contributed by each seed;
- wall-clock time and energy proxy per seed.

Continue to a larger budget only if the learning curve is still improving and the scientific decision remains unresolved.

## Selection rule

Select the smallest candidate satisfying all mandatory conditions.

### Mandatory capability conditions

```text
hidden exact accuracy:       20% to 70%
valid parse rate:            at least 95%
held-out structures:         clearly above chance
learning curve:              not flat or unstable
```

### Mandatory diversity conditions

Across independently trained seeds, require:

- imperfectly correlated semantic errors;
- unique valid clauses or counterexamples from different seeds;
- meaningful disagreement on held-out tasks;
- no single seed dominating every task family.

Provisional useful-disagreement target:

```text
pairwise complete-answer disagreement: 15% to 60%
```

### Mandatory efficiency condition

The selected scale must be cheap enough to support:

- four independently trained population members;
- multiple independently trained populations;
- same-weight controls;
- additional-sampling controls;
- ablations and failed runs.

Do not choose a larger model for a small accuracy improvement if it materially reduces the number of independent populations that can be trained.

## Decision tree

```text
PC-4M reaches the target capability and diversity range
→ select PC-4M

PC-4M is too weak, PC-10M reaches the range
→ select PC-10M

PC-10M saturates above 70%
→ increase task difficulty or select PC-4M

PC-10M is too weak, PC-18M reaches the range
→ select PC-18M, but inspect codec, curriculum, and supervision first

PC-18M also remains below 20%
→ do not automatically scale larger; diagnose task representation and training

all candidates exceed 70%
→ benchmark is too easy for the population-synthesis proof
```

## Current provisional selection

Until measured learning results exist:

\[
\boxed{\text{PC-10M: 8 layers, width 320, 5 heads, 9,859,840 parameters}}
\]

PC-4M and PC-18M remain required calibration controls.

## What this decision does not claim

This selection does not claim that 10M parameters are intrinsically optimal or that any model has learned the task.

It claims only that:

- the three exact architectures now exist;
- they satisfy the structural CPU contract;
- all three are plausible on the available GPU;
- measured CUDA, learning, diversity, and cost curves will choose the final scale.
