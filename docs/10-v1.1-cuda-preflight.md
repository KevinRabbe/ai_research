# V1.1 RTX 4060 Ti CUDA Preflight

## Purpose

This preflight measures whether PC-4M, PC-10M, and PC-18M can execute real mixed-precision training steps efficiently on the target RTX 4060 Ti 16GB.

It measures infrastructure only:

```text
forward pass
+ answer-only causal loss
+ backward pass
+ AdamW optimizer step
+ synchronization for timing
```

It does not train a scientific checkpoint and does not establish task capability.

```powershell
    origin/agent/plural-cognition-research-foundation

python -m pip install --upgrade pip

python -m pytest
```

First inspect the planned sweep without requiring CUDA:

```powershell
plural-cognition-cuda-preflight --list-only
```

Then run the complete target-machine sweep:

```powershell
plural-cognition-cuda-preflight `
    --models pc-4m pc-10m pc-18m `
    --sequence-lengths 128 256 `
    --microbatches 16 32 64 128 256 `
    --precision auto `
    --warmup-steps 5 `
    --measured-steps 20 `
    --vram-limit-gb 13.5 `
    --seed 20260806 `
    --output artifacts/cuda-preflight.json
```

The default sweep contains 30 candidate configurations.

## Before running

Close unrelated GPU-heavy programs where practical. In particular, avoid running games, local image generation, or another CUDA workload during the measurement.

Record the environment before execution:

```powershell
nvidia-smi
python -c "import torch; print(torch.__version__); print(torch.version.cuda); print(torch.cuda.get_device_name(0)); print(torch.cuda.get_device_capability(0)); print(torch.cuda.is_bf16_supported())"
```

The command also writes these fields into the JSON report.

## Precision selection

`--precision auto` chooses:

```text
bf16 when torch.cuda.is_bf16_supported() is true
otherwise fp16 with GradScaler
```

The chosen precision is recorded. Do not compare two reports as equivalent when their precision differs.

## Stop behavior

For each model and sequence length, microbatches are tested in ascending order.

The runner stops trying larger microbatches for that model/length boundary after:

- CUDA out-of-memory; or
- measured peak allocated memory exceeding 13.5GB.

This preserves roughly 2GB of the 16GB card for allocator fragmentation, evaluation, and temporary buffers.

A failed configuration is recorded rather than silently omitted.

## Report contract

The atomic JSON report includes:

```text
schema version
git commit
Python version
PyTorch version
CUDA and cuDNN versions
GPU name and compute capability
total VRAM
BF16 support
model name and exact parameter count
sequence length
microbatch
precision
warmup and measured steps
elapsed time
milliseconds per optimizer step
examples per second
tokens per second
peak allocated VRAM
peak reserved VRAM
loss
OOM or limit status
error text when applicable
```

The temporary report is renamed into place only after the full run completes.

## Qualification rules

The preflight is structurally successful only when:

1. the repository tests pass on the exact fetched head;
2. all three models complete at least one CUDA forward/backward/optimizer configuration;
3. measured losses are finite;
4. parameter counts match the fixed contracts;
5. the JSON records the actual RTX 4060 Ti and exact software environment;
6. at least one practical 256-token microbatch remains below the 13.5GB ceiling for each surviving model.

The fastest configuration is not automatically selected. The later learning curves still determine whether the model has enough capacity and remains unsaturated.

## Interpreting the result

For each model and sequence length, prefer the microbatch with the highest stable token throughput while remaining below the VRAM ceiling.

A larger batch is not better when:

- token throughput has stopped improving materially;
- peak memory removes the safety reserve;
- step-time variance becomes unstable;
- it prevents equal token-budget comparisons across model scales.

After selecting a physical microbatch, gradient accumulation may be used to equalize the global token batch across PC-4M, PC-10M, and PC-18M.

## Scientific boundary

This report can prove:

```text
the exact code executes on the target GPU
measured speed and memory for each configuration
which physical microbatches are practical
```

It cannot prove:

```text
the model learns Boolean mechanisms
the selected scale is scientifically sufficient
different seeds produce useful cognitive diversity
plural synthesis outperforms one model
```

Those claims require the subsequent 10M-token and 50M-token learning experiments.
