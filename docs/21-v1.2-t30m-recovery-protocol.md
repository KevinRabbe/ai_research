# V1.2-t30m recovery protocol

## Status

This document freezes the next capability-recovery intervention after the negative V1.2-t20m screen.

V1.2-t20m trained the PC-29M, PC-44M, and PC-64M capacity ladder under a nominal 20,000,000-token training horizon at initialization seeds 101 and 102. All six runs completed 611 optimizer steps, 20,021,248 effective padded tokens, and 78,208 training examples.

The corrected greedy final metrics were:

| Model | Seed 101 exact | Seed 102 exact | Mean exact | Mean semantic |
| --- | ---: | ---: | ---: | ---: |
| PC-29M | 0.152344 | 0.146484 | 0.149414 | 0.711396 |
| PC-44M | 0.156250 | 0.154297 | 0.155274 | 0.713837 |
| PC-64M | 0.144531 | 0.160156 | 0.152344 | 0.708801 |

All six final parse rates were 1.0. All three mean exact accuracies remained below the frozen 0.20 minimum, so V1.2-t20m selected no scale and seeds 103/104 were not trained.

## Learning-curve diagnostic

The exact 20M-horizon runs were evaluated at their own 10M and 15M checkpoints as well as the 20M final checkpoint. Aggregated across all six runs:

| Horizon checkpoint | Mean exact | Mean visible consistency | Mean semantic accuracy |
| --- | ---: | ---: | ---: |
| 10M | 0.116536 | 0.179993 | 0.680634 |
| 15M | 0.126302 | 0.201497 | 0.697418 |
| 20M | 0.152344 | 0.229167 | 0.711345 |

The final 5M-token interval improved mean exact accuracy by about 0.0260, larger than the approximately 0.0098 gain from 10M to 15M. Every model improved in exact accuracy from 15M to 20M. The evidence therefore does not support declaring the current learner plateaued at 20M.

Parsing is effectively solved while visible consistency, semantic accuracy, and exact reconstruction remain materially below ceiling. This indicates that the remaining limitation is task competence rather than output serialization.

## Frozen intervention

V1.2-t30m changes the training horizon from 20M to 30M nominal tokens while preserving the V1.2 capacity ladder and all other declared experimental factors.

Because the learning-rate schedule is token-indexed cosine decay whose progress depends on total `token_budget`, this intervention is accurately described as a **training-horizon extension under the frozen scheduler rule**, not as an isolated increase in consumed tokens with an identical intermediate learning-rate trajectory.

The following remain frozen:

- model family and order: PC-29M, PC-44M, PC-64M;
- initialization seeds: 101 and 102;
- data seed: 20260806;
- sequence length: 256;
- target tokens per optimizer step: 32,768;
- optimizer hyperparameters and scheduler rule;
- validation count and ordered validation shard: 512 examples;
- greedy generation for scale selection;
- minimum parse rate per seed: 0.95;
- mean exact-accuracy capability band: 0.20 through 0.70;
- selection rule: smallest qualifying model.

The recovery run identity is `v1.2-t30m-screen`.

## Checkpoint schedule

Each run uses:

```text
1M, 2M, 5M, 10M, 15M, 20M, 25M, 30M nominal tokens
```

At a 32,768-token optimizer batch, a 30,000,000 nominal-token horizon resolves to:

```text
optimizer steps:          916
effective padded tokens:  30,015,488
training examples:         117,248
```

## Training-data extension

Existing deterministic shards remain immutable:

```text
train-000: start_index=0      example_count=39,168
train-001: start_index=39,168 example_count=39,040
```

Only the missing contiguous suffix is generated:

```text
train-002: start_index=78,208 example_count=39,040
```

Together the ordered training shards contain exactly 117,248 examples. `train-002` must use the same data seed and training-data configuration as the existing training shards. The validation shard is not rebuilt or extended.

## Execution and provenance

All V1.2-t30m GPU-bound artifacts must be generated against one exact Git head:

1. run a new CUDA preflight for PC-29M, PC-44M, and PC-64M;
2. generate only `train-002` and preserve `train-000`/`train-001` unchanged;
3. resolve the six-run V1.2-t30m screening plan from that exact preflight;
4. bind all three ordered training manifests plus the existing validation manifest into fresh execution manifests;
5. dry-run all six executions;
6. train all six executions from initialization seeds 101 and 102 under the 30M intent;
7. greedily evaluate all six final checkpoints;
8. run scale selection under protocol label `v1.2-t30m` with the unchanged gates.

The 10M and 20M screening artifacts remain preserved as prior negative results. V1.2-t30m is trained from initialization rather than resumed from a 20M checkpoint because checkpoint manifests and scheduler trajectories are execution-bound.

## Decision rule

If at least one scale satisfies the parse gate and the 0.20-0.70 mean exact-accuracy band, select the smallest qualifying model and only then add initialization seeds 103 and 104.

If no scale qualifies, preserve V1.2-t30m as another negative result. Do not lower the gate, select the numerically best scale post hoc, or train seeds 103/104. Use the 20M, 25M, and 30M checkpoints to determine whether additional training horizon remains scientifically justified or whether the next intervention should target representation, supervision, or task interface.
